**Доручіть дизайн своєму агенту. Будьте вимогливим клієнтом. Доведіть якість дизайну свого сервісу до межі.**

Порівнюйте реальні варіанти UI/UX та обирайте потрібний напрям. Коли ви затвердите дизайн, агент застосує його до реального екрана й перевірить результат.

## Почніть зі свого агента

Скопіюйте цей запит у свого агента для розробки:

```text
Прочитай README за адресою https://github.com/daviddev90/picky-client.git і встанови picky-client у своєму середовищі агента.
```

Потім попросіть перший раунд у проєкті свого продукту:

```text
Використай picky-client, щоб створити 3–5 варіантів компонування цієї панелі керування. Збережи наявні кольори, шрифти та функції й дай мені порівняти варіанти в браузері перед вибором.
```

Агент досліджує приклади, створює варіанти, перевіряє їх відображення в реальному браузері та надає доступну вам URL-адресу для перегляду. Ви переглядаєте варіанти й обираєте.

## Як проходить раунд

Ця схема пояснює процес:

```mermaid
flowchart LR
    A[Визначити екран і рішення] --> B[Дослідити, створити й перевірити варіанти в браузері]
    B --> C[Ви порівнюєте й обираєте]
    C --> D[Ви схвалюєте наступний раунд або затверджуєте дизайн і його застосування]
    D -->|Наступний раунд| A
```

Кожен раунд визначає один ще не вирішений аспект дизайну. Ваші рішення зберігаються, тому наступний раунд розвиває те, що вам уже подобається.

| Що ви вирішуєте | Що ви порівнюєте |
|---|---|
| Настрій, візуальний характер або однаково зручні композиції | Десять різних напрямів |
| Компонування, елементи керування, щільність або навігацію | Від трьох до п’яти обґрунтованих варіантів із компромісами щодо зручності використання |
| Залишився один змістовний варіант | Обґрунтовану рекомендацію |
| Тему вже затверджено | Варіанти, що зберігають її кольори, характер шрифтів і матеріали |

## Оберіть, уточніть, застосуйте

Повідомте агенту, що ви обрали й що потрібно зробити далі. Приклади запитів:

```text
Я обираю #2. Далі запропонуй раунд із типографіки, зберігаючи це компонування.
```

```text
Дизайн затверджено. Застосуй #2 до реального екрана й перевір його поведінку та стани.
```

Перш ніж продовжити, агент чекає на ваше рішення. Застосування дизайну передбачає збереження наявних функцій, узгодження обраного компонування з реальним екраном і перевірку результату відображення.

## Що робить варіанти корисними

- **Реальні орієнтири:** кожен раунд досліджує сервіси з такою самою функцією або подібною роллю, а також актуальні підходи до дизайну.
- **Чесне порівняння:** усі візуальні варіанти використовують спільні перевірені тексти; затверджені дизайнерські рішення зберігаються.
- **Зручні варіанти:** відображення в браузері та навігацію перевіряють перед передачею вам, а доступна URL-адреса дозволяє оцінювати їх на вашому пристрої.
- **Історія рішень:** у `docs/picky-client.md` вашого проєкту записують варіанти, дослідження, перевірки та переможців. Затверджену специфікацію зберігають у `docs/picky-client-design.md`.
- **Чиста виробнича збірка:** тимчасове середовище перегляду та рядки його підключення до застосунку видаляють, а потім перевіряють їхню відсутність у виробничій збірці.

Надане середовище перегляду використовує React, TypeScript, Vite, React Router, Tailwind і Motion. Для інших стеків адаптують точки інтеграції; нативні продукти використовують попередній перегляд у вебі перед застосуванням у власному стеку. Середовища із субагентами делегують створення та перевірки. В інших середовищах етапи виконують послідовно й фіксують перевірку тим самим агентом.

### Для агента, що встановлює

Дотримуйся способу та області встановлення, які запросив користувач. В інших випадках використовуй наведений нижче нативний плагін для Codex або Claude Code, а для інших середовищ відповідний ID у Skills CLI. Нативні плагіни типово встановлюються для поточного користувача; Skills CLI типово встановлює в проєкт. Установи всю папку навички, включно з довідковими матеріалами, скриптами та ресурсами. Перевір, що середовище дійсно знаходить навичку, а потім повідом спосіб виклику та потрібні для цього середовища кроки перезавантаження.

### Skills CLI

Основна версія навички міститься в [skills/picky-client](skills/picky-client). Запусти [Skills CLI](https://github.com/vercel-labs/skills) із папки проєкту з Node.js 22.20.0 або новішою версією:

```bash
npx skills add daviddev90/picky-client --skill picky-client
```

Обери агента, коли з’явиться запит, або вкажи його явно:

```bash
npx skills add daviddev90/picky-client --skill picky-client --agent opencode -y
npx skills add daviddev90/picky-client --skill picky-client --agent antigravity -y
```

| Агент | ID `--agent` |
|---|---|
| Codex | `codex` |
| Claude Code | `claude-code` |
| OpenCode, зокрема oh-my-opencode | `opencode` |
| Antigravity IDE | `antigravity` |
| Antigravity CLI | `antigravity-cli` |
| Cursor | `cursor` |
| GitHub Copilot | `github-copilot` |
| Gemini CLI | `gemini-cli` |
| Cline | `cline` |
| Windsurf | `windsurf` |

Додай `-g` для встановлення в загальну папку агента для поточного користувача. Для ручного встановлення в проєкт скопіюй усю папку `skills/picky-client` до `.agents/skills/`, яку підтримують [OpenCode](https://opencode.ai/docs/skills/) та [Antigravity](https://antigravity.google/docs/skills?app=antigravity-ide). oh-my-opencode використовує встановлення навичок OpenCode.

### Плагін Claude Code

У терміналі, Claude Code 2.1.292 або новіша версія:

```bash
claude plugin install picky-client --marketplace daviddev90/picky-client
```

Для старіших версій:

```bash
claude plugin marketplace add daviddev90/picky-client
claude plugin install picky-client@daviddev90
```

У сеансі версія 2.1.275 або новіша підтримує `/plugin install picky-client --marketplace daviddev90/picky-client`. Див. [встановлення плагінів Claude Code](https://code.claude.com/docs/en/discover-plugins).

### Плагін Codex

```bash
codex plugin marketplace add daviddev90/picky-client
codex plugin add picky-client@daviddev90
```

Використай `/plugins` усередині Codex для перегляду плагінів. Див. [довідник Codex CLI](https://learn.chatgpt.com/docs/cli/reference).

Обидва плагіни використовують основну кореневу папку `skills/`. Кореневий [plugin.json](plugin.json) описує переносний плагін і плагін Codex; [.claude-plugin/plugin.json](.claude-plugin/plugin.json) забезпечує сумісність із Claude Code. Див. [пакування плагінів](https://developers.openai.com/plugins/build/plugins).
