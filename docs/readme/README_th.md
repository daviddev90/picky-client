**ให้เอเจนต์ของคุณออกแบบ คุณเป็นลูกค้าที่พิถีพิถัน ผลักดันคุณภาพการออกแบบบริการของคุณให้ถึงขีดสุด**

เปรียบเทียบแบบร่าง UI/UX ที่สร้างขึ้นจริง แล้วเลือกแนวทางที่ต้องการ เมื่อคุณยืนยันแบบแล้ว เอเจนต์จะนำไปใช้กับหน้าจอจริงและตรวจสอบผลลัพธ์

## เริ่มต้นกับเอเจนต์ของคุณ

คัดลอกคำขอนี้ไปยังเอเจนต์เขียนโค้ดของคุณ:

```text
อ่าน README ที่ https://github.com/daviddev90/picky-client.git แล้วติดตั้ง picky-client ในสภาพแวดล้อมเอเจนต์ของคุณ
```

จากนั้นขอรอบแรกในโปรเจกต์ผลิตภัณฑ์ของคุณ:

```text
ใช้ picky-client สร้างแบบร่างเลย์เอาต์ 3–5 แบบสำหรับแดชบอร์ดนี้ คงสี ฟอนต์ และฟีเจอร์เดิมไว้ แล้วให้ฉันเปรียบเทียบแบบร่างในเบราว์เซอร์ก่อนเลือก
```

เอเจนต์จะค้นคว้าตัวอย่าง สร้างแบบร่าง ตรวจสอบการแสดงผลในเบราว์เซอร์จริง และส่ง URL สำหรับรีวิวที่คุณเข้าถึงได้ คุณดูตัวเลือกแล้วตัดสินใจเลือก

## แต่ละรอบทำงานอย่างไร

แผนภาพนี้อธิบายกระบวนการ:

```mermaid
flowchart LR
    A[ระบุหน้าจอและสิ่งที่จะตัดสินใจ] --> B[ค้นคว้า สร้าง และตรวจสอบแบบร่างในเบราว์เซอร์]
    B --> C[คุณเปรียบเทียบและเลือก]
    C --> D[คุณอนุมัติรอบถัดไปหรือยืนยันแบบและนำไปใช้]
    D -->|รอบถัดไป| A
```

แต่ละรอบตัดสินใจเรื่องหนึ่งที่ยังเปิดอยู่ในการออกแบบ สิ่งที่คุณเลือกจะคงไว้ ทำให้รอบถัดไปพัฒนาต่อยอดจากสิ่งที่คุณชอบแล้ว

| สิ่งที่คุณตัดสินใจ | สิ่งที่คุณเปรียบเทียบ |
|---|---|
| อารมณ์ บุคลิกทางภาพ หรือองค์ประกอบที่ใช้งานสะดวกพอ ๆ กัน | แนวทางที่แตกต่างกันสิบแบบ |
| เลย์เอาต์ ส่วนควบคุม ความหนาแน่น หรือการนำทาง | ตัวเลือกที่มีเหตุผลรองรับสามถึงห้าแบบ พร้อมข้อแลกเปลี่ยนด้านการใช้งาน |
| เหลือตัวเลือกที่มีความหมายเพียงแบบเดียว | คำแนะนำพร้อมเหตุผล |
| กำหนดธีมไว้แล้ว | ตัวเลือกที่คงสี เอกลักษณ์ฟอนต์ และวัสดุของธีมไว้ |

## เลือก ปรับละเอียด นำไปใช้

บอกเอเจนต์ว่าคุณเลือกอะไร และต้องการให้ทำอะไรต่อ ตัวอย่างคำขอ:

```text
ฉันเลือก #2 ต่อไปเสนอรอบสำหรับตัวอักษร โดยคงเลย์เอาต์นี้ไว้
```

```text
ยืนยันแบบแล้ว นำ #2 ไปใช้กับหน้าจอจริง แล้วตรวจสอบพฤติกรรมและสถานะต่าง ๆ ของหน้าจอ
```

เอเจนต์จะรอการตัดสินใจของคุณก่อนดำเนินการต่อ การนำแบบไปใช้รวมถึงการรักษาฟังก์ชันเดิม ปรับเลย์เอาต์ที่เลือกให้เข้ากับหน้าจอจริง และตรวจสอบผลการแสดงผล

## สิ่งที่ทำให้ตัวเลือกมีประโยชน์

- **ตัวอย่างจริง:** แต่ละรอบค้นคว้าบริการที่มีฟีเจอร์เดียวกันหรือบทบาทคล้ายกัน รวมถึงแนวปฏิบัติด้านการออกแบบในปัจจุบัน
- **เปรียบเทียบอย่างเป็นธรรม:** แบบร่างทุกแบบใช้ข้อความชุดเดียวกันที่ผ่านการตรวจแล้ว และคงการตัดสินใจด้านการออกแบบที่ยืนยันแล้วไว้
- **แบบร่างที่ใช้งานได้:** ตรวจสอบการแสดงผลในเบราว์เซอร์และการนำทางก่อนส่งมอบ พร้อม URL ที่เข้าถึงได้เพื่อรีวิวบนอุปกรณ์ของคุณ
- **บันทึกการตัดสินใจ:** `docs/picky-client.md` ในโปรเจกต์ของคุณบันทึกแบบร่าง การค้นคว้า การตรวจสอบ และแบบที่ชนะ ส่วนข้อกำหนดการออกแบบที่ยืนยันแล้วอยู่ใน `docs/picky-client-design.md`
- **บิลด์สำหรับใช้งานจริงที่สะอาด:** ลบชุดรีวิวชั่วคราวและบรรทัดโค้ดที่เชื่อมเข้ากับแอป แล้วตรวจสอบว่าไม่มีสิ่งเหล่านี้อยู่ในผลลัพธ์บิลด์สำหรับใช้งานจริง

ชุดรีวิวที่ให้มาใช้ React, TypeScript, Vite, React Router, Tailwind และ Motion หากใช้ชุดเทคโนโลยีอื่น ให้ปรับจุดเชื่อมต่อ ส่วนผลิตภัณฑ์เนทีฟใช้พรีวิวบนเว็บก่อนนำแบบไปใช้ในชุดเทคโนโลยีของตนเอง สภาพแวดล้อมที่มีเอเจนต์ย่อยจะมอบหมายการสร้างและการรีวิวให้เอเจนต์ย่อย สภาพแวดล้อมอื่นทำแต่ละขั้นตอนตามลำดับและบันทึกว่าเอเจนต์เดียวกันเป็นผู้รีวิว

### สำหรับเอเจนต์ที่ติดตั้ง

ทำตามวิธีและขอบเขตการติดตั้งที่ผู้ใช้ร้องขอ หากไม่ได้ระบุ ให้ใช้วิธีติดตั้งปลั๊กอินเนทีฟด้านล่างสำหรับ Codex หรือ Claude Code และใช้ ID ของ Skills CLI ที่ตรงกับสภาพแวดล้อมอื่น ปลั๊กอินเนทีฟมีค่าเริ่มต้นเป็นการติดตั้งสำหรับผู้ใช้ปัจจุบัน ส่วน Skills CLI มีค่าเริ่มต้นเป็นการติดตั้งในโปรเจกต์ ติดตั้งโฟลเดอร์สกิลทั้งหมด รวมถึงเอกสารอ้างอิง สคริปต์ และไฟล์ประกอบ ตรวจสอบว่าสภาพแวดล้อมค้นพบสกิลจริง แล้วแจ้งวิธีเรียกใช้และขั้นตอนโหลดใหม่ที่สภาพแวดล้อมนั้นต้องการ

### Skills CLI

สกิลฉบับหลักอยู่ที่ [skills/picky-client](../../skills/picky-client) เรียก [Skills CLI](https://github.com/vercel-labs/skills) จากไดเรกทอรีโปรเจกต์ด้วย Node.js 22.20.0 หรือใหม่กว่า:

```bash
npx skills add daviddev90/picky-client --skill picky-client
```

เลือกเอเจนต์เมื่อระบบถาม หรือระบุโดยตรง:

```bash
npx skills add daviddev90/picky-client --skill picky-client --agent opencode -y
npx skills add daviddev90/picky-client --skill picky-client --agent antigravity -y
```

| เอเจนต์ | ID `--agent` |
|---|---|
| Codex | `codex` |
| Claude Code | `claude-code` |
| OpenCode รวมถึง oh-my-opencode | `opencode` |
| Antigravity IDE | `antigravity` |
| Antigravity CLI | `antigravity-cli` |
| Cursor | `cursor` |
| GitHub Copilot | `github-copilot` |
| Gemini CLI | `gemini-cli` |
| Cline | `cline` |
| Windsurf | `windsurf` |

เพิ่ม `-g` เพื่อติดตั้งในตำแหน่งของเอเจนต์ที่ใช้ร่วมกันได้สำหรับผู้ใช้ปัจจุบัน หากติดตั้งในโปรเจกต์ด้วยตนเอง ให้คัดลอกโฟลเดอร์ `skills/picky-client` ทั้งหมดไปที่ `.agents/skills/` ซึ่ง [OpenCode](https://opencode.ai/docs/skills/) และ [Antigravity](https://antigravity.google/docs/skills?app=antigravity-ide) รองรับ oh-my-opencode ใช้วิธีติดตั้งสกิลของ OpenCode

### ปลั๊กอิน Claude Code

ในเทอร์มินัล โดยใช้ Claude Code 2.1.292 หรือใหม่กว่า:

```bash
claude plugin install picky-client --marketplace daviddev90/picky-client
```

วิธีสำหรับเวอร์ชันเก่า:

```bash
claude plugin marketplace add daviddev90/picky-client
claude plugin install picky-client@daviddev90
```

ภายในเซสชัน เวอร์ชัน 2.1.275 หรือใหม่กว่ารองรับ `/plugin install picky-client --marketplace daviddev90/picky-client` ดู [การติดตั้งปลั๊กอิน Claude Code](https://code.claude.com/docs/en/discover-plugins)

```bash
codex plugin marketplace add daviddev90/picky-client
codex plugin add picky-client@daviddev90
```

ใช้ `/plugins` ภายใน Codex เพื่อดูปลั๊กอิน ดู [เอกสารอ้างอิง Codex CLI](https://learn.chatgpt.com/docs/cli/reference)

ปลั๊กอินทั้งสองใช้ไดเรกทอรีหลัก `skills/` ที่รากของคลังโค้ด [plugin.json](../../plugin.json) ที่รากใช้จัดแพ็กเกจปลั๊กอินแบบพกพา/Codex ส่วน [.claude-plugin/plugin.json](../../.claude-plugin/plugin.json) รองรับความเข้ากันได้กับ Claude Code ดู [การจัดแพ็กเกจปลั๊กอิน](https://developers.openai.com/plugins/build/plugins)
