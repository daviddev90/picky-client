설치 검증은 별도로 frontmatter, 참조 파일, 링크 해석, 임시 프로젝트에서 scaffold 실행,
Codex `skills/list`의 활성 등록을 확인한다.


## 2026-10-13 간결성 개정 확인

Anthropic의 [스킬 작성 모범 사례](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)와 OpenAI의 [스킬·프롬프트 재검토 글](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)을 실제 검색·열람하고, 설치된 skill-creator 지침에 따라 개정했다. 본문은 447줄·32,113바이트에서 134줄·8,806바이트로 줄었다.

`example)` 한 줄과 리서치, 관련 실제 서비스 조사, 사용자 선택, 고정 테마, 위임, 후속 후보 구성, 접근성·언어, 개발 하네스 제거, 최종 실제 적용 계약을 보존했다. 기본 화면 확인과 추가 후보별 `browserRenderCheck`를 구분하고, 긴 참조 6편의 목차·연결과 검색 예시의 시점 고정을 정리했다.

검증 기준은 결과를 보기 전에 고정했고 작성자에게 시험 요청을 제공하지 않았다. 부모가 다음 결과를 실제 확인했다.

- `quick_validate.py` 결과는 `Skill is valid!`였고, `git diff --check` 오류는 없었다.
- 상대 파일·절 링크 63개에서 오류가 없었고 필수 참조 7개가 연결되어 있었다. 없는 파일, 없는 절, 필수 참조 누락을 넣은 대조 사례 3개로 검사기의 판별도 확인했다.
- 파일 집합과 스크립트·템플릿 자산을 보존했다. 작성자와 부모가 전문을 검토한 뒤, 새 확인자 `/root/revision_check`가 새로 바뀐 부분만 검토하여 PASS로 판정했다.

`gpt-6.1-sol` 확인자 `/root/forward_check_a`와 `/root/forward_check_b`는 스킬 사본을 명시적으로 읽고 독립적인 읽기 전용 준비 답변을 각각 3건 작성했다. 부모가 총 6건의 전문을 읽어 아래 판정이 일치함을 확인했다. 이 기록의 실행 범위는 스킬 읽기와 설계 준비 답변 작성이다.

| 평가 범주 | 확인한 판정 | 결과 |
|---|---|---|
| 기존 테마에서 기능 배치 | 기능 라운드 3~5개, 고정 테마와 기존 기능 보존, 실제 서비스 조사 계획, `off`에서도 기본 화면 확인 | 두 확인자 일치 |
| 새 취향 선택 | 취향 라운드 10개, 실제 서비스 조사 계획, 사용자 선택 이후 후속 후보 구성과 진행 절차 | 두 확인자 일치 |
| 단일 표시 수정 | picky-client 적용 여부를 구별하고 해당 수정의 준비 작업을 제시 | 두 확인자 일치 |

위 확인은 2026-09-07 표에 남아 있는 자동 스킬 선택 시험과 별도로 기록했다. 평가 범주와 판정을 기록하고 시험 요청의 원문은 규칙·예시에 추가하지 않았다.
